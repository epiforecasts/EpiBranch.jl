What each model applies ​

One specification, a ModelSpec with its interventions, means the same thing to every model that reads it. Models differ in what they keep: individuals, counts of cases by type, or compartments by mixing group. A model with no individual to offer an intervention to applies only an intervention that describes its effect on a group. It refuses any other in the same words as every other such model.

The three kinds of model are:

  • Individuals: simulate on a model of people, such as BranchingProcess, HomogeneousProcess, MixingProcess or a network or household model. It applies every intervention.

  • Counts by type: simulate_by_generation on a BranchingProcess, which keeps the number of cases and susceptibles of each type.

  • Compartments by mixing group: MixingMeanFieldProcess, MixingLinearNoiseProcess and HybridProcess, which keep susceptible, infectious, removed and vaccinated compartments for each mixing group.

One budget, or one per group ​

A dose budget limits the reach of an intervention. Given as a number or a schedule, budget_per_period is one pool shared by every group, in every model. A PerGroup gives each group of the Population of the model its own budget, as a number or a schedule:

julia
doses = PerGroup(
    :under5 => 10.0,
    :over5 => Steps([7.0, 14.0], [0.0, 50.0, 0.0]),
)
campaign = CapacityConstrained(
    GroupVaccination(efficacy = 0.9, group_key = :age);
    budget_per_period = doses, period = 1.0
)
process = MixingProcess(
    population = Population([300, 700]; groups = ["under5", "over5"]),
    mixing_by = (:age,), mixing = FrequencyDependent([0.5 0.1; 0.1 0.5])
)

The groups are those of the population: the groups of a grouped population, or 1, 2, ... when it names none. A group of the population missing from the mapping is an error. An unknown name is also an error, so a mistyped name cannot pass as a scenario with no doses. To give a group no doses, give it a budget of 0. A population with no groups has none to name. PerGroup is refused there. PerGroup also sets the places of a HeldCapacity per group. It works with every intervention with a budget, including one written outside the package.

RingVaccination, MassVaccinationyesrefusedrefused
Isolation, ContactTracing, HeldCapacity and any other intervention, alone or under CapacityConstrained (shared or PerGroup budget)yesrefusedrefused

A model that cannot apply a specification raises an ArgumentError naming the specification it cannot apply, followed by the same list of what it reads: a GroupVaccination, alone or under Scheduled (a start_time and end_time only) and CapacityConstrained (one per campaign, with a shared or PerGroup budget and on_refusal = DropRefused()). A model that keeps counts or compartments also refuses, and names, any input it cannot represent, such as a distribution as efficacy, a delay_to_immunity or waning. The docstring of each model lists them.

An intervention written outside the package opts in to counts and compartments by defining EpiBranch.count_dosing, a description of its effect on a group. Without it, every model of counts or compartments refuses it.

The test file test/test_engine_support.jl runs every kind of model against this table. If the input a model reads changes, the test fails until the table is updated.
